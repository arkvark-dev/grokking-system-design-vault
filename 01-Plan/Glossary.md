## Core terms
| Term | Your definition | Note |
| --- | --- | --- |
| Latency | Time for one request to finish. | |
| Throughput | Work per unit time (QPS, RPS). | |
| Availability | Fraction of time the system can do useful work. | |
| Reliability | Probability of correct service over a period. | |
| Durability | Stored data is still there after crashes. | |
| Consistency | Whether replicas agree, and when readers see writes. | |
| Scalability | Ability to take more load by adding resources. | |
| Fault tolerance | System keeps working when parts fail. | |
| Replication | Extra copies of data or services. | |
| Partition / shard | Split data across nodes by a key. | |
| Hotspot | One shard or key gets too much traffic. | |
| Cache | Fast store of data that may be stale. | |
| TTL | Time to live before a cache or DNS record expires. | |
| CDN | Edge caches close to users. | |
| Load balancer | Spreads traffic across backends. | |
| Queue | Buffer between producers and consumers. | |
| Pub-sub | Many subscribers get the same events. | |
| Idempotent | Same request twice has the same effect. | |
| SLO | Target for a service level indicator. | |
| SLI | The metric you measure (for example p99 latency). | |
| Error budget | Allowed unreliability in an SLO window. | |
| Blast radius | How much breaks when one part fails. | |
| Backpressure | Slow down producers when consumers cannot keep up. | |
| Fan-out | One write becomes many downstream writes or sends. | |
| Geo index | Structure that answers 'near this point'. | |
